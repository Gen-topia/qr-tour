# 디자인 가이드 — 토큰 시스템 & 리스킨 방법

이 프로젝트는 **디자인 토큰(CSS 변수) 기반**이라, `src/app/globals.css` 상단의 `:root` 변수만 바꾸면
버튼·카드·배경·탭바 등 앱 전체 톤이 한 번에 바뀝니다. Tailwind 없이도 리테마가 빠른 이유예요.

## 1. 토큰 목록 (이걸 바꾸면 전체가 바뀜)

`src/app/globals.css`의 `:root`:

| 토큰 | 역할 | 현재값 |
|---|---|---|
| `--night` | 기본 배경 | `#141a2e` |
| `--night-2` | 카드/패널 배경 | `#1e2740` |
| `--ink` | 가장 짙은 곳(입력창·버튼 글자) | `#0d1120` |
| `--lantern` | **주 강조색**(버튼·링크·포인트) | `#e8a13a` |
| `--lantern-dim` | 주 강조색 어두운 변형 | `#b57b26` |
| `--talisman` | 보조 강조색(경고·삭제) | `#c8452e` |
| `--paper` | 기본 텍스트 | `#f3ecd9` |
| `--paper-dim` | 흐린 텍스트(보조 설명) | `#b9b19a` |
| `--line` | 테두리·구분선 | `#303b5c` |
| `--radius` | 모서리 둥글기 | `14px` |
| `--shadow` | 그림자 | `0 10px 30px rgba(0,0,0,.45)` |
| `--maxw` | 모바일 프레임 최대폭 | `420px` |

이 외에 톤에 영향 주는 것:
- `body`의 `background`(그라데이션)와 `font-family`
- `.lantern`(등불 애니메이션 원) — 시그니처 요소. 다른 컨셉이면 이걸 로고/아이콘으로 교체 가능.
- 컴포넌트 클래스: `.btn`(+`.ghost`,`.danger`), `.card`, `.input`, `.gauge`, `.badge`, `.frame`, `.tabbar`, `.tab`.

## 2. 리스킨 절차 (Claude가 따를 순서)

1. **참고 이미지 읽기** — `reference/screens/`(화면), `reference/inspiration/`(톤) 이미지를 본다.
2. **디자인 언어 추출** — 이미지에서 아래를 뽑는다:
   - 팔레트: 배경 / 주색 / 보조색 / 텍스트 색 (HEX로)
   - 타이포: 느낌(둥근/각진/고딕/명조), 굵기, 자간
   - 형태: 모서리 둥글기, 그림자 유무/세기, 여백 밀도
   - 무드: 밝음/어두움, 미니멀/장식적
3. **토큰에 매핑** — 위 값을 `:root` 변수에 대입. (색 이름과 실제 색이 안 맞으면 주석도 갱신)
   - 예: 밝은 테마면 `--night`→흰색계열, `--paper`→진한 글자색으로 **명암을 뒤집어야** 함. 이때 `body` 배경, `.btn` 글자색(`--ink`) 대비도 함께 점검.
4. **컴포넌트 미세조정** — 토큰만으로 안 되는 부분(버튼 채움/외곽선 스타일, 카드 그림자, 탭바 모양)은 해당 클래스에서 조정.
5. **폰트 교체(선택)** — 시안이 특정 서체 느낌이면 웹폰트 추가. Next에서는 `next/font`로 로드해 `--font` 토큰에 연결 권장(성능·CLS 안전).
6. **검증** — 모바일 360px에서 안 깨지는지, 텍스트 대비(가독성)가 충분한지 확인.

## 3. 반드시 지킬 규칙

- **구조·클래스명은 유지.** 색/폰트/모서리/간격만 바꾼다. `className`을 갈아엎지 말 것(전 컴포넌트 깨짐).
- **모바일 360px 우선.** `--maxw`, `.frame`, `.tabbar`는 함부로 늘리지 않는다.
- **대비 확보.** 배경-텍스트 명도 대비를 충분히(가독성). 밝은 테마로 뒤집을 땐 `--ink`/`--paper` 관계를 반드시 재점검.
- **한 곳에서.** 색은 컴포넌트에 하드코딩하지 말고 토큰을 참조. 새 색이 필요하면 `:root`에 토큰을 추가.
- **안전하게 한 화면씩.** 먼저 `main`만 맞춰 확인 → OK면 전체 확장.

## 4. 밝은 테마로 뒤집는 예시(감 잡기용)

```css
:root {
  --night:   #ffffff;   /* 배경 흰색 */
  --night-2: #f6f7fb;   /* 카드 연회색 */
  --ink:     #ffffff;   /* 버튼 글자(주색 위) → 흰색 */
  --lantern: #4f7cff;   /* 주색 파랑 */
  --lantern-dim:#3a5fd0;
  --talisman:#e5484d;
  --paper:   #1c2333;   /* 텍스트 진한 남색 */
  --paper-dim:#6b7280;
  --line:    #e5e7eb;
  --shadow:  0 8px 24px rgba(20,30,60,.10);
}
/* body 배경 그라데이션도 밝게 바꿔야 함 */
```
> 실제로는 `reference/` 이미지에서 뽑은 값으로 채운다. 위는 "명암을 어떻게 뒤집는지"만 보여주는 예시.

## 5. Tailwind, 꼭 필요할까?
- **리테마(톤 바꾸기)만이 목적이면 필요 없음.** 지금 토큰 시스템이 더 빠르다.
- Tailwind가 유리한 경우: 앞으로 **새 화면을 유틸리티 클래스로 빠르게** 많이 만들 때.
- 도입 시 주의: 기존 컴포넌트가 전부 커스텀 CSS 클래스라, Tailwind를 깔아도 **기존 화면이 자동으로 바뀌지 않음**(수동 변환 필요). 설치 방법은 `docs/Tailwind_도입(선택).md` 참고.
